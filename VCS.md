# What is VCS

**VERSION CONTROL SYSTEM**

    This allows multiple users to work on simultaneously without overwriting each other’s work. 
    It registers all project changes, storing them in a central database (repository or “repo”), 
    offering the chance to easily review, revert, or branch out.

    It’s a tool or system that helps developers track and manage changes to code or files over time. 
    It records every modification, who made it, and when.

Here’s a breakdown of what VCS does:

1. **Tracks changes** – Every time you modify a file, the VCS records the change so you can see the history.


2. **Collaboration** – Multiple people can work on the same project simultaneously without overwriting each other’s work.


3. **Versioning** – You can go back to previous versions of your code if something breaks.


4. **Branching and merging** – You can create separate “branches” for new features or experiments and later merge them into the main codebase.


5. **Backup and recovery** – VCS acts like a backup system because all previous versions are stored and can be restored.


# What VCS are available

 **Distributed VCS, or DVCS** every user has a complete copy of the repository, <br>
allowing for local commits and operations without needing to connect to a central server. <br>
Other commonly used DVCS include **Mercurial** and **Bazaar**, **Git**

**Centralized Version Control System (CVCS)**, where a single central repository that all users commit to and pull from. <br>
If you're looking to get started, we would recommend going for **Subversion (SVN)** or **Perforce**.

**Local Version Control System** works with simple systems that track changes locally on a single machine, <br>
it's often used for managing versions of files without collaboration. <br>
The most popular system for this is **RVS (Revision Control System)**.
