# POSIX standard streams and stream redirection

У каждого процесса есть 3 стандартных потока данных.
В POSIX-системах (Linux, Unix, BSD, macOS) каждая программа по умолчанию получает три потока ввода-вывода:

| Название | File Descriptor | Назначение | Описание |
|----------|----------------|-----------|----------|
| stdin | 0 | Standard Input | Откуда программа читает |
| stdout | 1 | Standard Output | Куда программа пишет результат |
| stderr | 2 | Standard Error | Куда программа пишет ошибки |

❗ stdout и stderr — это разные каналы, даже если они выглядят одинаково в терминале.
```
stdin (0) — стандартный ввод
Это клавиатура по умолчанию.
cat
Ждёт ввод → ты печатаешь → выводит в stdout.
```
```
stdout (1) — стандартный вывод
Обычно терминал.
echo "hello"
Текст выводится на экран.
```
```
stderr (2) — стандартный вывод ошибок
Тоже обычно терминал, но логически — другой поток.
ls /no_such_dir
Ошибка идёт через stderr, а не stdout.
```

## Почему stderr не объединён с stdout?

ПРИЧИНЫ:
- stacktrace не должен загрязнять вывод
- логи должны писаться отдельно
- stdout можно пайпить
- stderr НЕ должен ломать формат

## Stream redirection (перенаправление потоков)

Ты можешь сказать shell’у:
не выводи на экран — запиши в файл / передай программе / выбрось

| Синтаксис | Что делает | Пример / Пояснение |
|-----------|------------|------------------|
| `>` | Перезаписать файл (stdout → файл) | `command > file.txt` |
| `>>` | Добавить в файл (append) | `command >> file.txt` |
| `2>` | Перенаправление stderr в файл | `command 2> error.log` |
| `2>&1` | stderr → stdout | `command > output.log 2>&1` |
| `<` | stdin ← файл | `command < input.txt` |
| `|` | Передает stdout одной программы в stdin другой | `command1 | command2` |


### Перенаправление stdout

```
В файл (перезаписать)
echo "hello" > file.txt
В файл (добавить)
echo "hello" >> file.txt
```

### Перенаправление stderr

```
ls /no_dir 2> error.log
```

### Перенаправление stdin
```
Ввод из файла вместо клавиатуры:
cat < file.txt
```

### Объединение stdout и stderr

```
Перенаправить оба в один файл:
command > all.log 2>&1

Порядок важен.
Сначала stdout → файл, потом stderr → stdout.
```

### Перенаправление "в никуда"
```
Уничтожить вывод:
command > /dev/null
Уничтожить и stdout и stderr:
command > /dev/null 2>&1
/dev/null — это "чёрная дыра".
```

### Pipes (каналы)

```
Передают stdout одной программы в stdin другой:
ls | grep ".txt"
stdout(ls) → stdin(grep)
```
